# 我的翻译（My Translator）

选中网页上的文字，鼠标旁边就弹出一个浮窗，点一下原地看译文。
翻译走你**自己的**接口 —— 默认接本机的 [web-to-openapi](#依赖本机翻译服务)，不经过任何第三方服务器，也不用注册账号。

支持 Edge / Chrome 及所有 Chromium 内核浏览器（Manifest V3）。

> 仓库：<https://github.com/dengzhh/my-translator>

## 功能

| 能力 | 说明 |
|---|---|
| **划词即译** | 选中任意文本，浮窗出现在鼠标右上角，点一下出译文 |
| **快捷键** | `Alt` + `T` 直接翻译选中文本，跳过浮窗 |
| **右键菜单** | 右键 → 「用「我的翻译」翻译选中文本」 |
| **一键复制** | 译文面板里直接复制结果 |
| **切换目标语言** | 面板内切换语言，立刻重译，不用重新选中 |
| **暂停划词** | 不想被打扰时点 `❚❚` 临时关掉自动弹出，`Alt`+`T` 仍可用；图标上带徽章提醒 |
| **多种接口** | 本机翻译服务 / OpenAI 兼容（智谱、DeepSeek、硅基流动、Ollama…）/ DeepL / Google 翻译 / 自定义 HTTP |
| **译文缓存** | 相同原文 + 相同目标语言命中缓存，不重复请求 |
| **设置不打断浏览** | 设置面板直接在**当前网页里**展开，网页不会被跳走、也不会被新标签页顶掉 |

## 快速开始

**三步，两个项目**：先装翻译服务（本机接口），再装这个插件。

### 第一步：装本机翻译服务

插件默认调用 `http://127.0.0.1:8090/api/v1/translate`，这个服务由 **web-to-openapi** 提供 ——
一个把「浏览器里能看到的网页能力」包装成本地 HTTP 接口 / MCP 服务的开源项目，翻译接口是它内置的能力之一，
调用的是百度翻译网页版，**免登录、免费、不需要任何 API Key**。

> 项目地址：<https://github.com/dengzhh/web-to-openapi>
>
> 详细文档：[README](https://github.com/dengzhh/web-to-openapi#部署只需一次) ·
> [API 说明](https://github.com/dengzhh/web-to-openapi/blob/main/API.md) ·
> [排障手册](https://github.com/dengzhh/web-to-openapi/blob/main/TROUBLESHOOTING.md)

安装步骤（只需做一次）：

1. **准备 Node.js**，并确认它在**浏览器的** PATH 里（不只是你的终端里能跑，见下方注意）
2. 下载 / 克隆 web-to-openapi 仓库
3. **注册本地服务**：双击 `host\install.bat`
   （等价于 `powershell -ExecutionPolicy Bypass -File host\install-host.ps1`，写入当前用户注册表，不需要管理员权限）
4. **加载它的扩展**：打开 `edge://extensions`（Chrome 为 `chrome://extensions`）→ 开启开发者模式 →
   「加载已解压的扩展程序」→ 选它的 `extension/` 目录
5. 加载后服务会自动启动，确认一下：

   ```bash
   curl http://127.0.0.1:8090/health
   ```

   看到 `"status": "ok"` 就通了。

> ⚠️ **最容易踩的坑**：在 cmd 里 `node -v` 能用，不代表浏览器能找到 node。
> 本地服务由浏览器拉起，继承的是**浏览器进程**的环境变量。改完 PATH 需要**完全退出浏览器**
> （任务管理器里不能剩 `msedge` / `chrome` 进程）才生效。
> 判定与修法见 [TROUBLESHOOTING.md](https://github.com/dengzhh/web-to-openapi/blob/main/TROUBLESHOOTING.md#为什么-cmd-里-node-能跑浏览器却说找不到)。
>
> ⚠️ **换浏览器要注意**：两个浏览器同时加载它，会各拉起一个服务进程争抢同一个 8090 端口。
> 建议只用其一，或在它的设置里给其中一个换端口（插件这边同步改一下「接口地址」即可）。

### 第二步：装本插件

1. 打开 `edge://extensions`（Chrome 为 `chrome://extensions`）
2. 开启 **开发者模式**
3. 点 **加载已解压的扩展程序**，选择**本仓库根目录**（`manifest.json` 所在的那一层）
4. 装好后随便打开一个网页划词试试

**不需要填任何 Key**。默认配置已经指向本机服务：

| 项 | 默认值 |
|---|---|
| 接口地址 | `http://127.0.0.1:8090/api/v1/translate` |
| 引擎 | `baidu` |
| 目标语言 | 简体中文 |

### 第三步（可选）：换成云端接口

本机服务没启动、或者想用别的渠道时，点浮窗上的 ⚙（或扩展图标 → 设置），
设置面板会在**当前网页里就地展开**，切到「接口」标签换类型：

| 服务商 | 接口地址 | 模型 | 密钥申请 |
|---|---|---|---|
| 本机服务（默认） | `http://127.0.0.1:8090/api/v1/translate` | 引擎 `baidu` | 无需密钥 |
| 智谱 GLM | `https://open.bigmodel.cn/api/paas/v4/chat/completions` | `glm-4-flash` | open.bigmodel.cn |
| DeepSeek | `https://api.deepseek.com/v1/chat/completions` | `deepseek-chat` | platform.deepseek.com |
| 硅基流动 | `https://api.siliconflow.cn/v1/chat/completions` | `Qwen/Qwen2.5-7B-Instruct` | cloud.siliconflow.cn |
| 本地 Ollama | `http://localhost:11434/v1/chat/completions` | `qwen2.5:7b` | 无需密钥 |

选预设会自动填好地址和模型，再填 Key，点「测试翻译」确认能通即可。

支持的接口类型：

- **本机翻译服务（web-to-openapi）** —— `POST /api/v1/translate`，语言代码映射与取值都在插件内完成
- **OpenAI 兼容** —— 上表这些，以及任何 `/v1/chat/completions` 风格的网关
- **DeepL** —— Free / Pro 均可
- **Google 翻译** —— Cloud Translation API Key
- **自定义 HTTP** —— 自己写请求头、请求体模板和取值路径

## 使用

| 操作 | 效果 |
|---|---|
| 选中文本 | 鼠标右上角弹出浮窗「翻译为 简体中文」 |
| 点击浮窗按钮 | 展开译文面板 |
| 点击气泡右侧 `❚❚` | 暂停划词浮窗，右下角提示条可一键恢复 |
| `Alt` + `T` | 直接翻译当前选中文本（跳过浮窗） |
| 右键选中文本 | 「用「我的翻译」翻译选中文本」 |
| 面板内切换语言 | 立刻重译 |
| `Esc` | 关闭浮窗 |
| 点 ⚙ / 扩展图标 → 设置 | 在当前网页里就地展开设置面板，网页不受影响 |
| 拖动面板标题栏 | 移到不挡文字的位置 |

浮窗会自动避让选中的文字（压到就移到选区上方）；页面滚动时跟随文本；点击页面空白处收起气泡但保留译文面板。

### 暂停划词浮窗

点气泡右侧的 **`❚❚`**：立刻收起浮窗，页面右下角弹出「划词浮窗已暂停」+「恢复」按钮（9 秒后自动消失）。

暂停期间选中文字不再弹窗（状态同步到所有标签页），但 `Alt`+`T` 和右键菜单**仍然可用**；
扩展图标显示 `❚❚` 徽章，不会让你忘了自己关过。

## 关于设置面板

所有设置都在**当前网页**的浮层里完成，分「接口 / 语言 / 测试」三个标签。
插件不会导航你正在看的页面，也不会用新标签页把它顶掉 —— 这是本项目的硬性设计约束，
不是"顺手优化"：任何会离开当前页面才能改的配置，都算设计缺陷。

唯一会新开标签页的情况是**首次安装时**的引导页（那时你不会正在看什么网页）。

## 隐私

- 默认只和你**本机**的 `127.0.0.1:8090` 通信；换成云端接口后，文本才会发往你填的那家服务
- API Key 存在 `chrome.storage.local`，不参与浏览器账号同步，也不会下发给网页侧（内容脚本拿到的配置已剔除密钥）
- 译文缓存同样只在本机，默认最多 300 条，可在设置里清除
- 主机权限为 `<all_urls>`：因为接口地址由你自己填，扩展无法预先知道域名

## 常见问题

**浮窗没出现？**

1. **点一下扩展图标**，面板顶部会告诉你当前页面状态：

   | 显示 | 含义 | 怎么办 |
   |---|---|---|
   | ✓ 本页已就绪，可直接划词 | 正常 | 在正文段落上拖选试试 |
   | ✗ 本页未加载脚本（装插件前打开的页面） | 页面比插件更早打开 | 点「注入本页」，或 F5 刷新 |
   | 当前是浏览器内置页面，扩展无法注入 | `edge://` 设置页、新标签页、PDF | 换普通网页 |

2. 确认加载的是**仓库根目录**（选错会报「清单文件缺失」）
3. 确认面板里的「启用」开关是打开的
4. PDF、图片里的文字、`chrome://` 页面、iframe 里的文字都不支持

**译文显示「连接失败」/「服务未就绪」？**

先确认本机服务活着：`curl http://127.0.0.1:8090/health`。
打不通就回去看 [web-to-openapi 的排障文档](https://github.com/dengzhh/web-to-openapi/blob/main/TROUBLESHOOTING.md)。

**提示语言代码不支持？**

本机服务只接受它支持的 54 种语言代码，传不认识的代码会直接返回 `400`（而不是静默翻错语种）。
插件已内置代码映射：`zh-CN→zh`、`zh-TW→cht`、`ja→jp`、`ko→kor`、`fr→fra`、`es→spa`……

**翻译有点慢？**

百度翻译网页版首次调用要加载整站，约 3~5 秒；命中标签复用后约 2 秒；相同请求直接命中缓存（毫秒级）。
这是上游翻页机制的固有开销，与插件无关。

## 目录结构

```
manifest.json                 MV3 清单
background/service-worker.js  翻译引擎：请求、缓存、权限、右键菜单
content/content.js            选区监听 + Shadow DOM 浮窗（含设置面板）
lib/langs.js                  语言表
options/                      整页设置（仅首次安装引导与注入失败时兜底）
popup/                        点扩展图标弹出的小面板
icons/                        图标
```
